# Pi packages installed on every machine, declaratively.
#
# WHERE THIS FILE LIVES
#   ~/.pi/agent/pi-packages.txt, and setup_env.sh rsyncs this checkout's config
#   into ~/.pi/agent, so in the repository it is pi/agent/pi-packages.txt.
#   @darkrei08/setup-ai's `pi-packages` module resolves exactly this path (an
#   explicit PI_PACKAGES_FILE wins first) and runs `pi install` once per line,
#   then verifies the source landed in ~/.pi/agent/settings.json. Re-running is
#   idempotent, so a fresh clone converges on the same set without anyone
#   hand-editing settings.json.
#
# FORMAT
#   One source per line; blank lines and `#` comments are ignored. Supported
#   sources are exactly what `pi install` accepts:
#     npm:<package>[@<version>]
#     git:<host>/<owner>/<repo>[@<ref>]
#     <path>                     local checkout, absolute or ~/...
#
# DELIBERATELY NOT LISTED
#   * pi-extensible-workflows, gentle-pi, pi-mcp-adapter: setup-ai owns these.
#     Its `pi-workflows` module installs pi-extensible-workflows (published
#     release or patched local build), and its `gentle-ai` module runs
#     `pi install npm:gentle-pi` + `npm:pi-mcp-adapter` and verifies both in
#     settings.json. They stay OUT of this manifest so the module keeps
#     ownership, but they ARE listed in settings.json: setup_env.sh rsyncs that
#     file over ~/.pi/agent, so an entry only the module added would be dropped
#     by the next dotenv run (the module then fails its own verification).
#   * github:darkrei08/pi-cockpit-tools-sync: pi parses a bare `github:` source
#     as a LOCAL path (it has neither a protocol nor the `git:` prefix, so
#     pi 0.85 parseSource does not read it as a git URL). That is a checkout
#     inside ~/.pi/agent, which a manifest cannot recreate.
#   * @sting8k/pi-vcc: dropped as a Pi package (it is a second
#     session_before_compact provider and conflicts with pi-codex-context, which
#     requires sole compaction ownership). It stays only as an npm dependency in
#     pi/agent/npm and is loaded for workflow children via the extensions glob.
#
# KEEPING THIS IN SYNC
#   The list mirrors the remote sources in pi/agent/settings.json. A package
#   added there belongs here too, so the next machine that clones dotenv gets it.
#
