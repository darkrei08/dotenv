# Domain docs

This repository uses a single-context layout.

## Read before exploring

- Read `GLOSSARY.md` at the repository root when it exists.
- Read relevant ADRs under `docs/adr/` when they exist.
- If a future `GLOSSARY-MAP.md` appears, follow it instead of assuming one context.

## Vocabulary

Use terms as defined by the glossary in issue titles, plans, tests, and review notes. If a needed concept is missing, either use the repository's existing wording or record the gap for domain modeling.

## ADRs

Surface conflicts with existing ADRs instead of silently overriding them. Add an ADR only for a hard-to-reverse, surprising decision with a real trade-off; do not create ADRs for routine configuration edits.
