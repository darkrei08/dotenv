# CLIProxyAPI-First Model Fit Report

Date: 2026-10-19
Scope: tracked Pi workflow and `pi-ext-roles` configuration in this repository.

## Decision

Normal workflow roles use `cliproxyapi/*` directly. Native providers and OpenCode Go are not normal role targets. They remain explicit emergency failover candidates only, because choosing an OpenCode Go route for GPT-6 Luna consumes the wrong provider plan/quota and changes the cost boundary.

This report is based on the local Pi catalog and tracked configuration. CLIProxyAPI availability is runtime evidence from `pi --list-models cliproxyapi`; public catalogs do not prove gateway access.

## Why Gemini 3 was selected

Gemini 3.8 Flash High is not the base model for coding or review. It is a fallback because it provides:

- 1M context and 65.5K maximum output in the local CLIProxyAPI catalog.
- Reasoning support and `low`/`medium`/`high` thinking levels in the public Google catalog for the Gemini 3.x family.
- Flash/high-throughput latency characteristics suitable for scout, summary, and bounded recovery work.
- A distinct provider/model path from Claude and GPT routes, improving failover diversity.
- Lower expected token cost than frontier reviewer routes, while still clearing the 32K output floor for developer/test/reviewer recovery.

Newer does not automatically mean fitter. A newer model is eligible only when the exact CLIProxyAPI route is listed, its context/output limits meet the role, its effort levels map correctly, its plan/quota boundary is known, and a focused task shows better cost per completed unit. Gemini 4 Argon and OpenCode Go models remain out of the automatic base matrix because the current evidence does not establish the desired CLIProxyAPI route and plan boundary.

## Role rubric

1. Verify the exact bridge/provider first; a model on the wrong bridge is not a fit.
2. Require context >= 200K for repository-wide scout/research and >= 200K for developer/test/reviewer work.
3. Require max output >= 32K for developer, tests-expert, reviewer, oracle, architect, security, and release work.
4. Choose the lowest effort that clears the task; reserve high/xhigh for deep reasoning, tests, research, and review.
5. Prefer the cheapest and fastest model that clears the capability bar, measured by cost per completed task rather than token price alone.
6. Keep `reserveTokens >= max(maxTokens, 16384)`; use a measured 80-85% trigger for long tool-heavy sessions.
7. Do not substitute an unverified model silently. Fail over only through the configured matrix.

## Automatic matrix

`pi/agent/ha-failover.example.json` is CLIProxyAPI-only. The bootstrap uses `PI_HA_GROUP` when a workflow launcher supplies a role-specific profile; otherwise it uses the live `activeGroup` or `defaultGroup`. It never infers a role from a model ID, because models such as GPT-6 Luna intentionally appear in multiple profiles.

- `development`: GPT-6 Luna -> GPT-6.1 Sol -> Gemini Pro Agent
- `scout`: GPT-6 Luna -> Gemini 3.8 Flash High
- `fast`: Claude Sonnet 5.5 -> Gemini 3.8 Flash High
- `research`: GPT-6 Luna -> Gemini Pro Agent
- `summary`: Claude Haiku 5.5 -> Gemini 3.5 Flash Lite
- `testing`: GPT-6 Luna -> Gemini 3.8 Flash High
- `reviewer`: Claude Opus 5.5 -> Gemini Pro Agent -> GPT-6 Luna

`setup_env.sh` copies the credentials-free template and runs `pi-ha ensure`. The command creates `~/.pi/agent/ha.json` only when absent; otherwise it adds missing managed groups/defaultGroup without overwriting credentials, active routing, or custom groups.

The matrix handles the installed HA extension's quota/capacity/authentication paths. The repository-owned `pi-ha-bootstrap.mjs` also selects an available matrix entry at startup and, after an unknown-provider/model error, switches and replays the failed prompt once, without changing credentials or the configured settings.
